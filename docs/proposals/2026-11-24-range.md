# Proposal: Feather Range, a library for any design, composed in seconds

Status: **approved in order by the owner (2026-11-24); wave 1 is built (1.19.0).** The decisions in §10 are still open. Written 2026-11-24, after Feather 1.18.0.

## 1. The goal

Qooler draws a direction as a short `feather.page` spec, and Feather renders it. **A direction should take under 30
seconds**, against 9.4 minutes today, when Opus writes every direction as free HTML and CSS. To get there, Feather
has to cover whatever Qooler wants to draw, so a direction becomes three things and no code:

1. a choice of **blocks and layouts**;
2. their **variants and knobs**;
3. the brand's **tokens**.

The owner's words: "enrich feather design system as much as possible to cover even heavy motion and animation and
three js and webgl components as well, various types that can be reused fast by theming and quick adjustment and
customization". Also: "a Mother of all design systems, highly customizable, semantics well defined and organized,
design tokens fully detailed"; "as various as possible to cover any kind of design, heavy or small basic, but
perfectly fine tuned smooth, with micro animations and micro motions"; "detail eye and eyes for perfection is the
key"; "Goal is satisfying UI and experience".

**Where the 30 seconds goes.** `feather-page build` renders the reference page (5 static routes, 72 KB) in 0.09 s
on the owner's Mac (measured 2026-11-24). On a 2-CPU server that is still well under a second, so rendering is not
the cost. The cost is the model writing the spec, so the spec must be **short**: a block name, a variant, a few
knobs. Every design decision that today lives in hand-written CSS has to become a named, bounded, validated value.

**The source.** Qooler's pattern catalog: `knowledge/27-award-pattern-catalog.md` (Qooler 1.43.2), with
`knowledge/research/2026-11-24-pattern-catalog.json` (`qooler.pattern-catalog/1`). It holds 272 patterns: motion 55,
scroll 51, UI 52, 3D/WebGL 70, 20 from the 2026 winners (§6 S), and new performance and access families (§7).
§7 also reads the shipped front-end code of 388 winners and writes down 228 techniques with their values
(`research/2026-awards/code-tricks-1..4.jsonl`). Feather takes the techniques and values, never their code. Every family below cites catalog ids.
§6 measures 492 award-winning sites from 2026 (Awwwards, CSS Design Awards, FWA; 403 verified on their award
pages), and each pattern carries `seen_2026`, how many of those sites name it. The counts are floors: a pattern is
counted only when its award page names it.

**What the 2026 winners do most** (sites of 492):
- **The edges come first:**
  - page transition 49, preloader 47, 404 scene 45, intro scene 37;
  - overlay menu 36, footer scene 32, contact 26.
- **Then:** layered parallax 37, sound 24, infinite scroll 19, interactive WebGL hero 15, film hero 12.

So the moves most often finished as scenes are arrival, the menu, transitions, the footer and the 404. Feather's
strongest defaults must be there (§5 H, milestone R2).
- **Tech:** GSAP is on 173 of 378 sites, WebGL on 165, Three.js on 108.
- **Colour:** 286 of 323 palettes are two colours, and 108 add exactly one saturated accent.
- **In the winners' own code (of 388):** Lenis on 261, SplitText on 144, ScrollTrigger scrub on 151 and pin on 59,
  a custom cursor on 101, a capped DPR on only 55. The median page ships 933 kB of script, against Feather's
  110 kB (§6).

**The edge.**
- On 208 developer-scored pages, animation averages 7.84 and accessibility 6.87; 195 of the 208 score animation
  higher.
- WebGL sites score the same on accessibility as the rest (6.88 against 6.85). Rich motion doesn't cost access;
  the winners just skip the access work.
- Feather keeps the motion and makes access the default. Every pattern ships its tiers (full, reduced motion, and
  no-JS or no-WebGL), and the gates prove each one.

## 2. What 1.18.0 already gives

- `feather-tokens/3`: open fonts, the fluid display scale, signature curves, `pace`, the expression roles, and the
  `surface`, `contrast` and `focus` axes.
- `@aleeforoughi/feather-expression` primitives:
  - layout: Section, Stage, Split, Grid, Bento;
  - type and media: DisplayTitle, MediaFrame, Marquee, Reel, Counter;
  - pointer: Magnetic, Cursor;
  - scroll, routes and 3D: Scroll, Transition, World;
  - infrastructure: one clock, a DPR cap, reduced-motion mapping.
- `@aleeforoughi/feather-living`: the Living Page.
- `feather.page/0`: 13 blocks, each with fixed fields, one default design each, and a `signature` escape hatch.
- Gates: hygiene, the rendered audit, axe, visual regression, and the website layer (mobile budgets, frame rate,
  reduced motion).

**The gap:**
- A block has one look. There are no variants, no loudness, and no knobs.
- There is no scroll choreography beyond reveal and Stage.
- There is no 3D beyond the World contract: the renderers are the site's own code.
- There is no micro-motion library on product atoms.
- Galleries, navigation, loaders, comparisons and footers are missing.

## 3. The model: one token system, three layers

### 3.1 Tokens: primitives → semantic roles → component tokens

Every visual property of every component resolves through this chain: no raw values (the hygiene gate already
enforces this for product UI and the website packages). A brand file re-skins everything; a page spec adjusts
through knobs, never through CSS.

| group | primitives | semantic roles (new in **bold**) | component tokens |
|---|---|---|---|
| colour | the palette ramps the engine builds; the default is a ground, an ink and one accent (as 286 of 323 winners' palettes) | fg/bg/surface/line/accent roles, **`block-1..4`** (colour-blocked sections), **`scrim`**, **`ink-on-media`** | per slot, `slot.variant` |
| type | families, fluid scale | `type-*`, `type-display-*`, `font-voice`, **`type-kinetic`** (display sizes kinetic patterns may use) | per slot |
| space and size | 4 px steps | density (`tight`, `default`, `spacious`), `section-space-*`, **`container-*`** | per block |
| shape | radius tiers, step | control, card, dialog, inset, concentric | per slot |
| elevation, blur and opacity | shadow-1..3, blur scale | `surface` axis, **`overlay-*`**, **`opacity-*`** (dim, muted, disabled) | per slot |
| z-index | **scale: base, raised, sticky, overlay, modal, toast, cursor** | **`layer-*`** | per block |
| motion | durations, curves; the curve set gains the winners' measured curves: **`wipe` (.76,0,.24,1)** for wipes and fills, **`route` (.625,.05,0,1)** for page changes, beside expo-out (.16,1,.3,1) and the overshoot (.34,1.56,.64,1) | product roles, expression roles, **micro-motion roles** (§5 A), **`intensity`** | per pattern |
| sound | **a bed and a cue set (files the brand ships), volume, ducking** | **`sound.*`**, off until the person turns it on | per cue |
| loudness | **0–3** | **`--loudness`** read by every pattern (§3.3) | per pattern |
| 3D material and light | **from the palette: ground, key, rim, emissive, fog, particle ramp, grade** | **`scene.light`** (studio, dusk, night), **`scene.material`** (matte, gloss, glass, chrome), **`scene.post`** (none, soft, film, glow) | per scene |
| media | **aspect set, focal point, treatment (`clean`, `duotone`, `grain`, `scrim`)** | **`media.*`** | per frame |

All of this lands as an **additive `feather-tokens/4`**. `/3` and `/2` brands stay byte for byte, as /3 did for
/2. Defaults come from the brand's existing axes: a `paper` brand gets matte material, and a `film` brand gets film
post. A brand gets every new role without writing a line.

### 3.2 Taxonomy

| level | what | package |
|---|---|---|
| foundations | tokens, engine, foundation.css | `feather-tokens` |
| atoms, molecules, organisms | product UI (exists), plus the micro-motion layer on every interactive atom | `feather-react` |
| expression primitives | website atoms and molecules: type, media, layout, pointer | `feather-expression` |
| **behaviour layers** | **motion, scroll and scene**: attach to any block, never a block of their own | `feather-expression` (motion, scroll), **`feather-scene` (new, 3D and WebGL)** |
| blocks and layouts | page sections, each with named variants | `feather-page` |
| templates | whole pages: portfolio, studio, product, launch, editorial, event | `feather-page/templates` |

Each level is built only from the one below. A block never writes CSS a primitive could own. A behaviour layer
never knows which block it is on: it reads the block's `data-slot`s.

### 3.3 Loudness, one quality at every volume

`loudness` 0–3 is one knob on the brand (its default) and on every block (its override):

| | 0 quiet | 1 composed | 2 expressive | 3 spectacle |
|---|---|---|---|---|
| motion | micro-motion only | reveals | kinetic type, parallax, pinned scenes | full choreography |
| scroll | native | reveals | pins and scrubs | camera flights |
| 3D | none | poster or still | ambient shader, turntable | full scene, particles, post |
| example | a form, a docs page | a company site | an agency site | a launch, a world |

The finish is the same at every level: anatomy, states, optical alignment, focus, both themes, three devices. A
loudness-0 page passes the same detail pass as a loudness-3 one. Loudness is capped by the device tier (§6), so
"3" on a weak phone renders as "2" or "1" automatically.

## 4. The knobs a page spec can set (`feather.page/1`, from wave 2)

Additive: every `/0` document stays valid. Every knob is an enum or a bounded number, validated with a JSON pointer
and a code, like `/0`. Every knob has one documented meaning, and an unknown value is an error, never a guess.

```json
{
  "schema": "feather.page/1",
  "brand": "brand/tokens.json",
  "loudness": 2,
  "template": "studio",
  "sections": [
    { "block": "hero", "variant": "giant-type", "title": "…", "media": "reel.mp4",
      "motion": { "enter": "split-lines", "intensity": 0.6 },
      "scene": { "kind": "shader", "preset": "gradient-noise", "quality": "auto" } },
    { "block": "work", "variant": "hover-list", "items": ["acceptto", "freezon"],
      "scroll": { "pattern": "stagger-grid", "from": "start" } },
    { "block": "story", "variant": "pinned-steps", "steps": [ … ],
      "scroll": { "pattern": "pin", "length": 3, "scrub": true, "snap": "steps" }, "tone": "inverse" },
    { "block": "gallery", "variant": "rail", "items": [ … ], "loudness": 1 }
  ],
  "transitions": { "route": "curtain", "direction": "up" }
}
```

| knob | where | values |
|---|---|---|
| `variant` | every block | the block's named variants (§5) |
| `loudness` | page, block | 0–3 |
| `tone` | block | base, subtle, raised, inverse, block-1..4 |
| `space` | block | s, m, l, xl |
| `align` | block | start, center, split |
| `motion.enter` | block, item | none, fade, rise, mask, split-lines, split-words, split-chars, clip, blur, scale-in |
| `motion.intensity` | block | 0–1 (scales distance, scale and rotation, never duration) |
| `motion.direction` | block | up, down, left, right, center-out |
| `motion.stagger` | block | none, tight, default, loose (bounded by the 1.2 s cap) |
| `scroll.pattern` | block | reveal, stagger-grid, pin, horizontal, parallax, stack, scale-to-full, fill-text, scrub-media, theme-switch |
| `scroll.length` | pinned patterns | 1–4 viewport heights |
| `scroll.scrub` / `snap` | pinned patterns | true or catch-up seconds / none, steps, sections |
| `scene.kind` | block | shader, particles, model, depth-image, camera-path, splat, world |
| `scene.preset` | per kind | named presets (§5 F) |
| `scene.quality` | block | auto (default), high, mid, low, poster |
| `media.treatment` | media | clean, duotone, grain, scrim |
| `media.focal` | media | x, y as 0–1 |
| `transitions.route` | page | none, crossfade, shared, curtain, circle, slices, pixel, dissolve |
| `loader` | page | none (default), counter, logo, words, scene |
| `sound` | page | none (default), cues, bed-and-cues (always off until the person turns it on) |
| `cursor` | page | native (default), follower, label |

Two rules keep this from becoming CSS in disguise:
- **There are no free numbers** beyond the few bounded ones above.
- **Knobs compose: they never fight.** The validator rejects contradictions with a code, such as a pinned
  `scroll.pattern` on a block inside a `horizontal` one, or `scene` at loudness 0.

## 5. The component families

Each family is a set of reusable parts with named variants. Catalog references are in brackets, by family and
row: Motion (§1), Scroll (§2), UI (§3), 3D (§4), and S1–S20 for the 2026 winners (§6 S). `seen_2026` counts are in
parentheses. "Mobile" is the pattern's 390 px form: same, simplified or off.

**H. The edges, first** (the most named moves of 2026; each a finished block at every loudness)

The first variants come with the values read in winners' code (§7). These are starting values: each becomes a
named default, adjustable by knobs within bounds.
- **Honest loader:** progress is the lesser of real readiness and elapsed time over a minimum (2.4 s on a first
  visit, 1.4 s on a return, 8 s cap). `role=status`, skipped under reduced motion.
- **Loader that docks into the header:** a 3.2 s fill, then a 900 ms dock, every step on the one clock.
- **View-transition page change:** the old page scales to 0.9; the new page wipes in from
  `inset(100% 0 0 0)` over 0.95 s on `wipe`. The header keeps its own transition name.
- **Parallax push:** the old page moves to -25vh while the new one rises from 100vh, 1.2 s. Instant under reduced
  motion.
- **Column curtain:** 4 columns, 1.12 s each, 0.06 s stagger.

- **`loader`** (preloader 47, intro scene 37):
  - variants: counter tied to real progress, logo build (SVG stroke draw), word cycle, scene intro (shader, at the
    scene tier);
  - hands off into the hero (Flip or a View Transition);
  - rules: a cap of about 2–3 s, a skip, never on repeat visits, never hides content from crawlers or screen
    readers, and the LCP is never held without cause.
- **Route transitions** (49, plus 12 View Transitions): the D family below, as a page-level knob. Pixel-grid
  dissolve [S7] joins its variants.
- **`nav`** (overlay menu 36):
  - variants: overlay menu with staggered masked links, minimal bar that hides on scroll, index progress,
    channel-surf [S4];
  - brand-own navigation [S3] is the `signature` route: built over a real list of links, tested against the
    conventional menu before it ships;
  - every variant has a focus trap, Escape, `aria-expanded` and focus restored.
- **`footer`** (32): variants: giant wordmark, reveal from behind (fixed footer), scene (a small toy or shader),
  plain. Every link stays text.
- **`404`** (45): variants: type scene, playful scene, minimal. A clear way home.
- **`contact`** (26): gains variants: giant email, short form, booking [S15].

**I. Sound** (24; a layer like motion, never a block) [S1, S2]
- Measured defaults:
  - a mixer with bed, effects and interface buses, ducking, and a compressor (-6 dB, ratio 12);
  - section loops faded by scroll position (desktop only);
  - a low-pass sweep when an overlay opens;
  - an `aria-pressed` toggle.
- An ambient bed and interaction cues, **off until the person turns it on** (WCAG 1.4.2).
- The mute is always visible and remembers its state; one audio context starts on a gesture.
- Audio-reactive visuals [S2] drive a scene's uniforms from frequency bands, with a calm still when sound is off
  or motion is reduced.
- Anything said has text.

**J. Product flows in a page** [S6, S11, S12, S14–19]
- **Choices and flows:** view-mode switch (grid, list, index), interactive quiz, booking flow, pricing calculator
  (the total in `aria-live`), theme toggle (token sets, `prefers-color-scheme` first).
- **Media and data:** data visualization (end state plus table), map navigation (always a list of places with the
  same links), podcast player (chapters, transcript), avatar configurator.
- Most of this already exists as product atoms and organisms in `feather-react`, so these are blocks that compose
  them, not new atoms.
- The in-page assistant [S13] is the Living Page (1.18): it's already built.

**A. Micro-motion, on every interactive atom by default (product UI and sites)** [Motion F40–45, H51–55]
- Roles:
  - press (scale 0.97, 100–150 ms);
  - hover in and hover out;
  - focus (the ring draws, never jumps);
  - toggle (a spring, 150–250 ms);
  - loading (skeleton and spinner);
  - success, error (a 2–4 px shake plus text and `aria-live`);
  - enter and leave (menus, dialogs, toasts);
  - link underline wipe, button label roll, field label float.
- Mechanics:
  - all of it through `useThemeMotion`, so a brand's `pace` and `signature` reach every atom;
  - interruptible and reversible: nothing snaps.
- Reduced motion: colour or opacity only, and feedback stays.
- Measured: feedback in the next frame, under about 100 ms.

**B. Type in motion** [Motion B10–19, Scroll H33–37]
- Measured defaults:
  - masked line rise: yPercent 110 → 0, 0.8 s, stagger 0.1, expo-out;
  - character skew-slide: x 80, skewX 14, stagger 0.02, only at ≥ 992 px with no reduced motion;
  - per-character stagger 0.01–0.03 s, per line 0.05–0.1 s.
- Primitive: `KineticTitle` (extends DisplayTitle).
- Variants: split-lines, split-words, split-chars, scramble, word-swap, fill-on-scroll, velocity-skew,
  variable-axis, marquee (scroll-linked).
- Plus `svg-stroke-draw` [S8] for marks, logos and lines.
- Always one real heading with the full string; the pieces are `aria-hidden`.

**C. Scroll choreography** (a behaviour layer) [Scroll A–L]
- reveal (CSS `view()` first, the observer as fallback), stagger-grid;
- pinned storytelling: `pin` with steps, sticky visual, pin-and-swap;
- horizontal (a pinned track, or a native snap rail on touch);
- parallax depth: layers, inner image, zoom-through, which must have a reduced path;
- stacking cards, scale-to-fullscreen, section curtain;
- scrubbed media: an image sequence, video, or Lottie;
- section theme switch, chapter nav, progress.
- The driver is chosen per pattern: CSS scroll-driven where it suffices (off the main thread), the one clock for
  pins and sequences, Lenis only where smoothing earns it, and native on touch.
- Never scroll-jacking; nothing reachable only by scroll position.

**D. Page and route transitions** [Motion A1–9]
- Variants: crossfade, shared element (View Transitions; Flip fallback), curtain (single and multi-strip), circle
  from the tap point, page slide, title card, WebGL dissolve (scene tier only).
- Scroll is restored and focus moves to the new `h1`; real URLs.

**E. Media** [UI A1, E31–34, Motion C20–26]
- Film hero: full-bleed video with a poster as the LCP, a scrim held at 4.5:1, a pause control, and the poster
  alone on data saver.
- Showreel player with captions.
- Galleries:
  - rail (native snap);
  - masonry;
  - grid with hover reveal;
  - hover-list preview;
  - 3D disc (scene tier);
  - wheel or ring, by drag or scroll, with arrow keys stepping one [S5];
  - lightbox (`feather-react` has one: extend it, don't duplicate it).
- Infinite loop (19) for galleries and pages: clones are `aria-hidden` and a way out stays.
- Image treatments: clip reveal, inner parallax, blur-to-sharp, duotone, grain.

**F. Scene: 3D and WebGL** (new package `feather-scene`, lazy, never on the critical path) [3D A–R]

Every scene is a `WorldRenderer` (the 1.18 contract): one clock, capped DPR, on-demand frames, paused offscreen,
disposed on route change, with a poster slot and a DOM text slot.
- **Shader backgrounds:** gradient-noise, aurora, fluid (cursor), flowmap, caustics, grain field. One full-screen
  triangle; 3–5 palette tokens; 0.5–1.0 resolution.
- **Particles:** ambient dust, cursor field, morph between shapes, text-to-particles, image-to-particles, GPGPU at
  the high tier.
- **Object viewer:** turntable, orbit-inspect (keyboard arrows and preset angles), hotspots (focusable buttons
  mirrored in a list), configurator (real radio buttons), exploded view, AR quick look.
- **3D hero stage:** studio stage (self-hosted environment, contact shadow), lightformer rig, float idle,
  reflective floor, fog.
- **Image-to-depth:** a depth-map parallax from a photo and its depth image (the depth map is made offline by
  Qooler's media pipeline, never at runtime), plus a layered diorama.
- **Scroll camera flights:** camera on rails (waypoints, look-at, damping 0.2), scene switch, pinned 3D sequence,
  scroll product reveal.
- **Materials and post:** transmission glass (CSS `backdrop-filter` fallback), matcap chrome, soft blob; one merged
  effect pass (bloom, film grain and vignette, tone LUT from the palette), and depth of field on desktop only.
- **Later:** Gaussian splats, data globe, physics playground, character world, WebXR [S20] (only ever optional).
  Each needs its own owner decision.

**G. New page blocks and layouts** (`feather-page`) [UI B–K]

Beyond the edges (H) and flows (J): `gallery`, `story` (pinned steps), `comparison` (native range), `testimonials`,
`journal`, `form` (minimal underline, conversational stepper).

Existing blocks gain variants:
- hero: giant-type, split, film (12), product, interactive (15);
- work: grid, hover-list, fullscreen-cases, bento;
- numbers: plain, counter-roll;
- logos: grid, marquee;
- offer: cards, table, toggle;
- quote: large, rail.

Layouts: editorial-asymmetric, swiss-grid, brutalist, poster [S10], colour-blocking, two-colour ground. Templates compose blocks
into whole pages.

## 6. Performance budgets and fallbacks

**Mid-range phone** (the gate's 4× CPU-throttled Pixel 7 profile, as in 1.18):

| | loudness 0–1 | loudness 2 | loudness 3 / scene |
|---|---|---|---|
| LCP | ≤ 2.0 s | ≤ 2.5 s | ≤ 2.5 s (poster is the LCP) |
| CLS | ≤ 0.05 | ≤ 0.1 | ≤ 0.1 |
| TBT | < 100 ms | < 200 ms | < 200 ms (the scene loads after first paint) |
| INP | ≤ 200 ms | ≤ 200 ms | ≤ 200 ms |
| frame rate, median scroll | ≥ 58 | ≥ 55 | ≥ 50, never below 30 for long |
| JS on first load (gzip) | ≤ 90 KB | ≤ 110 KB | ≤ 110 KB, plus scene ≤ 160 KB lazy |
| GPU | — | — | ≤ 100 draw calls, < 100k vertices, DPR ≤ 1.5, textures ≤ 2048, ≤ 3 lights |

These are starting values (convention), to be tightened by measurement. 1.18's sites already measure TBT 0–17 ms
at 4× locally after `mountPage`.

**2-CPU server** (Qooler's renderer):
- `feather-page build` of one direction, all routes, in ≤ 500 ms;
- the validator in ≤ 20 ms;
- the theme compile in ≤ 50 ms;
- no headless browser needed to produce a direction (screenshots are a separate, optional step);
- the gate measures this in CI with `taskset -c 0,1`.

**The performance and access family** (catalog §7; built once in `feather-expression/core`, used by every block):
- **pixel budget:** DPR ≤ 1.5 *and* a cap on total drawn pixels, frame time clamped to 1/20 s;
- **quality ladder:** a benchmark sets the tier, a tier drops when frames run long, and is re-tested later, never
  while the tab is hidden;
- **capability gate:** heavy WebGL only on desktop with no reduced motion, no data saver and enough memory. The
  verdict is remembered for 30 days, and everyone else gets the complete DOM page;
- **shader prewarm:** compiles one shader per frame behind the loader;
- **proximity mount:** heavy pieces mount only near the viewport;
- **motion opt-in:** spatial motion runs only under `prefers-reduced-motion: no-preference`;
- **always:**
  - every loop pauses when the tab is hidden, and sound mutes;
  - never take over the wheel or block pinch-zoom;
  - scrambled or split text keeps a label.

  These are where the winners most often fail.

**Device tiers and fallbacks.** Every pattern ships every tier, and the gate renders each one:
- **full**;
- **reduced motion:** spatial motion becomes a fade of 150–200 ms or the end state, and feedback stays;
- **no-WebGL, low power or data saver:** the poster plus the DOM text, the same layout, nothing missing;
- **no-JS:** static and fully readable, from `feather-page build`.

`scene.quality: auto` picks high, mid, low or poster from device hints and a live frame-time monitor, and drops a
tier rather than dropping frames.

**Accessibility, the default and not an option:**
- WCAG 2.2 AA;
- the meaning always lives in the DOM (a canvas is decoration);
- one `h1`, real headings in reading order;
- a pause control for anything moving more than 5 s (2.2.2);
- no scroll-jacking, and focus managed on every transition;
- contrast held at every point of a transition and over media (the gate samples mid-transition frames);
- 44 px targets, keyboard and touch first-class.

## 7. The quality bar for every component

A component ships only when all of this holds (added to `FEATHER.md`):

1. **Mobile first:** designed at 390 px, then tablet, then desktop. Touch, pointer and keyboard are each tested.
2. **Deep token mapping:** no raw value. A story in the three /3 brands, and in a fourth brand made only of tokens,
   proves it re-skins.
3. **The detail pass:** anatomy, every state, optical alignment, the long, empty, error, loading and RTL cases,
   both themes, three devices.
4. **Gates:**
   - hygiene;
   - the rendered audit (product UI) or the website gates (frame rate, budgets, axe, reduced motion, no-WebGL);
   - visual regression across themes;
   - an e2e per tier.
5. **Satisfaction, measured:** 60 fps on the throttled phone for its interactions, feedback within about 100 ms,
   no layout shift.

## 8. How a missing block is added later

When Qooler needs something Feather lacks:

1. **Qooler files a gap** in the Feather repo (an issue, the `pattern-request` template). It holds:
   - the catalog id, or a new pattern described the same way (what, how, knobs, reduced motion, mobile);
   - a draft spec of the block or variant;
   - the brand that needs it;
   - evidence: a verified example or a measured need.
2. **It first tries to be a variant or a knob** of something that exists (FEATHER.md rule 2). A new block is the
   last resort.
3. **Feather builds it** through the same path as everything else:
   - spec table entry;
   - component from existing primitives;
   - stories in the three brands;
   - every tier and gate.

   It ships in a minor release with a CHANGELOG line naming the request.
4. **Qooler takes the release** (`tools/feather/vendor` from the wheel). Its own `signature` block covers the brand
   in the meantime.
5. **Target:** a variant or knob within a day of the request; a new block within a week.

## 9. Waves

The owner chose the order on 2026-11-24: the edges first, then text and scroll, sound and pointer, 3D, and the rest
of the catalog. Each wave is one minor release, merged only with the owner's approval.

## 10. Decisions for the owner

1. **The 3D stack** (Three.js is on 108 of 378 winners).
   - **Recommended:** plain Three.js behind Feather's own `WorldRenderer` contract, as an optional peer of
     `feather-scene`. It adds no React-three-fiber runtime, keeps one clock, and is the lightest.
   - Alternative: React Three Fiber and drei. Faster to build and their docs back many catalog patterns, but they
     add weight and a second render model.
2. **GSAP** (in the code of 272 of 388 winners; Lenis on 261).
   - **Recommended:** Feather's own clock plus CSS scroll-driven animations for everything it can, with GSAP as an
     optional peer for pins and sequences on sites that use it, as in 1.18.
   - The catalog notes that SplitText and ScrollSmoother were Club plugins. GSAP is reported to have made all
     plugins free in 2025 (unverified): check the current licence before Feather depends on any plugin. Until then,
     split text is Feather's own (it already is).
3. **`feather-tokens/4` and `feather.page/1` as additive versions.**
   - **Recommended:** yes, as with /3.
4. **Scope of "later" scenes** (splats, globe, physics, character worlds).
   - **Recommended:** not before R6, each only on a real brief.
5. **Clean-room rule.** Feather learns the winners' techniques and values but copies no code. One winner's
   cursor ports a component whose licence forbids redistributing it, so Feather builds its own. Every library's
   current licence is checked before Feather depends on it (GSAP plugins, Lenis, Rive, Theatre.js).
   - **Recommended:** yes, written into `FEATHER.md`.
6. **Rive** [S9] (interactive vector state machines) needs its runtime as a dependency.
   - **Recommended:** not now; SVG, CSS and the one clock cover the named uses. Revisit on a real brief.
7. **The `pattern-request` intake in §8** as the only way Qooler asks for a block.
   - **Recommended:** yes, so the library grows from need, not from the catalog's length.
