# feather-sdk

Write and check Feather Experience IR (`feather.ir/0`) from Python. Python 3.11 or later, no dependencies.

```sh
pip install feather-sdk
```

## Build an experience

One builder per node type, in `feather_sdk.nodes`. They take keyword arguments (so editors complete them), drop
`None`, set `type`, and return plain dicts. A field named like a Python keyword gets a trailing underscore:
`for_="rec"` writes `"for"`.

```python
from feather_sdk import experience, nodes, validate

doc = experience(
    "approve_campaign",
    [
        nodes.Recommendation(
            id="rec",
            intent="launch the recommended test",
            summary="Recommended test: 7 days, purchase objective",
            importance="high",
            reversible=False,
            expandable={"why": "Enough to test three creative directions without overspending."},
        ),
        nodes.IrreversibleAction(
            id="go",
            intent="confirm spend",
            consequence={"spend": {"amount": 1050, "currency": "AED"}},
        ),
        nodes.Alternative(id="less", intent="spend less", for_="rec"),
    ],
    locale="en",
)
```

Builders do not validate. `validate` does.

## Validate

`validate(document)` takes a dict or a JSON string and never raises. It gives the same issues as the TypeScript
`validate()` in `@aleeforoughi/feather-intent`: same codes, JSON Pointer paths, order and messages.

```python
result = validate(doc)
if result.ok:
    experience = result.experience
else:
    for issue in result.issues:          # Issue(code, path, message, node)
        print(issue.path, issue.code, issue.message)
    # or: print(format_issues(result.issues))
```

## Replies

`validate_reply(experience, reply)` checks what the person sent back: the node exists, takes the act, and the value is
encoded as the act requires. It validates the experience first.

```python
from feather_sdk import validate_reply

reply = {"experience": "approve_campaign", "node": "go", "act": "confirm"}
result = validate_reply(doc, reply)
result.ok                                # True
result.reply                             # the reply, as given
result.issues                            # [ReplyIssue(code, message)] when not ok
```

`acts_for(node)` lists the acts a node takes.

## How it stays in step with TypeScript

`feather_sdk/_spec.json` (the node table) and `feather_sdk/nodes.py` (the builders) are generated from
`packages/intent/src/spec.ts` by `pnpm --filter @aleeforoughi/feather-intent generate`. Do not edit them. The
validator is a port of `validate.ts` and `reply.ts`, and `conformance/parity/*.json`, generated by the TypeScript
validator, holds thousands of documents and replies with the answers Python must match. Run the tests with:

```sh
python3 -m unittest discover -s tests
```
